## Implementation Phases

### Phase 1: Reader-first result support

- [ ] **1.1** Register the nested `2.0.0` result body in both SDK lanes.
  — **Why:** A subcheck must own its findings, and readers need a version they can validate before producers are re-pinned.
  — **Done when:** Python and TypeScript accept the same schema and examples, reject flat rows in `2.0.0`, require row verdicts, and keep `1.0.0` as the default write version.
  — **Consumers affected:** CWE, IFC, and SDK clients that validate or read result bodies.
- [ ] **1.2** Add optional descriptions to node subcheck manifests.
  — **Why:** A generated catalog needs a useful description without invalidating an older published node.
  — **Done when:** Both SDKs accept and preserve a description, and existing manifests can still omit the field.
  — **Consumers affected:** Registered node manifests and the CWE catalog.
- [ ] **1.3** Extend the existing reader to preserve nested finding facts and references.
  — **Why:** Suggestion consumers need their existing compact queries, while report assembly needs original measurements and exact recorded limits.
  — **Done when:** Compact overview, failure paging, and element lookup still work on existing versions; `2.0.0` reads without materializing all measurements; lossless reads keep the original flat or nested index and return raw facts without guessing identities.
  — **Consumers affected:** CLS and IFC readers and the summary collector.

## Technical Notes

Baseline SDK `0384812`. Maintain result-file layout `1.1.0` for `2.0.0`; it supplies workflow revision and run data needed to recover the exact requirement. Keep optional recorded limits in v2 until the later producer ticket proves reconstruction. Body shape puts `measurements` under each check and keeps the counts per subject. Identity and geometry are independent. Optional original file attribution requires a verified element.

Read check descriptors separately from nested measurement events so field order cannot associate a reading with the wrong check, and overview never loads all geometry. Leave the existing `0.x` and `1.x` compact contracts alone; require exact `1.0.0` or `2.0.0` for lossless reads. TypeScript mirrors body validation and types; the file-staged streaming reader is the existing Python interface used by deployed consumers.

No writer defaults, workflow definitions, or deployed suggestion graphs change. The `.env.local` parity gate belongs to the later execution re-pin, not these additive reader changes.

## Risks & Mitigation

Use an anchored schema with an unambiguous check key. Preserve row order before filtering. Exercise a group without identity and a reason without geometry, verify that timestamps/headers still use the existing codec, and re-run legacy reader tests.
