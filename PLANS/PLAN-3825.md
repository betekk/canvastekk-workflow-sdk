## Technical Notes
- Lazy-import discipline (#104): auth.py backends import fastapi inside methods; node_token.py must stay stdlib-only, importable without fastapi/httpx.
- Cache: bounded verdict map; clear-on-overflow is acceptable (ponytail: per-token LRU when eviction storms are observed).
- Verify endpoint contract: `POST {base}/api/nodes/verify-token` body `{"token": ...}` → 200 `{"valid": true, "run_id", "node_id", "exp"}` or 200 `{"valid": false}`; 5xx/timeout = fail-closed 503 at the node. CWE implements in #3826.
- `_version.py` currently 0.37.3 vs pyproject 0.53.3 — bump_versions.py rewrites all; release-date feeds support-horizon (DA-3359).

## Risks & Mitigation
- Verify-endpoint contract ambiguity between SDK and CWE → single normative doc (5.1) + mint/verify primitives in one module both import.
- Fail-open accidentally introduced via cache of transport errors → errors are never cached (test asserts stub call count).
- TS/Python drift → identical semantics table in the contract doc; both test suites enumerate the same cases.
