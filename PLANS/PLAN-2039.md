## Design decisions (per-ticket "decide per-item" list)

1. **Release-asset upload (wheel + tgz)** — KEEP, as a chained prod-only job (reusable has no native asset step). Same asset names: `canvastekk_workflow_sdk-X-py3-none-any.whl` + `.sha256`, `canvastekk-workflow-sdk-X.tgz`.
2. **Tagged-commit build assertion** — KEEP (checkout `new_tag`, assert HEAD == tag SHA; DA-1302 class).
3. **Post-publish import verification** — KEEP both languages (pip install from registry with 3× retry; npm install + `VERSION` check).
4. **`sdk-released` dispatch** — KEEP verbatim semantics: GitHub App token (client-id `GH_APP_CLIENT_ID` per #152 standard) scoped to `canvastekk-workflow-nodes`, event `sdk-released`, payload `{sdk_version, environment: "prod", breaking, breaking_changes, released_at}`.
5. **Version-file rewrites** — RETIRE the committed flow; tag-derived ephemeral builds. `bump_versions.py` runs in the runner against `new_version` (bare); its output is never committed or pushed. In-repo version files freeze at the last-released value (cosmetic drift, same as the library pilots). `poetry lock --regenerate` drops out entirely — the committed lock stays consistent with the frozen pyproject (the poetry-2.x lock learning no longer applies to this path).
6. **`continue-on-error` placement** — PRESERVED EXACTLY where the hand-rolled workflow had it (registry publishes + registry verifies). The asset channel (what consumers pin) is strict; registry flakes must not fail the release. Deliberate semantics retention.
7. **Behavior deltas accepted (fleet standard, #3845/#3855):** prod bump source changes from cliff `--bump` (commit-derived) to **PR semver label** (`major`/`minor`/`patch`, default patch) — breaking commits need the `major` label to mint a major; committed `chore(release): prepare` commits and committed CHANGELOG.md growth stop — Release notes (cliff `--latest`) carry forward.

## Technical Notes

- mathieudutour outputs: `new_tag` v-prefixed, `new_version` bare — bump script regex `^\d+\.\d+\.\d+` requires the bare form.
- Reusable's dev lane uses the same tag-action settings as the SDK's current `dev-tag` job (`pre_release_suffix: dev`, `tag_prefix: v`, `default_bump: patch`) → seamless counter continuity.
- Reusable's pick-runner (`runner_pool: auto`) reads `vars.GH_APP_ID` — present (`3911716`) alongside the SDK's `GH_APP_CLIENT_ID`; probe needs no changes.
- Old `release` job's `github.actor != 'github-actions[bot]'` guard drops: nothing pushes commits back anymore (changelog/version stamps are ephemeral), and the reusable owns `release-<ref>` concurrency.

## Risks & Mitigation

- **First prod run mints wrong bump** (label-driven now) → dry-run step 2 uses an explicit `patch` label; counter lane unaffected.
- **Ephemeral stamp misses a version source** → enumeration already covers all five files (DA-3425 rule verified this session); no files added/moved here.
- **Registry publish flakes fail the release** → `continue-on-error` retained on registry steps exactly as before; asset channel (consumer-pinned) stays strict.
