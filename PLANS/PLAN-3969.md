## Implementation Phases

### Phase 1 (engine): array sessions + dispatch derivation

- [ ] **1.1** `mint_session(..., array: bool = False)` stores the flag; the initiate route accepts optional body `element: {"index": int ≥ 0, "suffix": str}` — array sessions REQUIRE it (non-array sessions reject it); server derives key `f"{record.key}/{index}{sanitized(suffix)}"` where sanitize keeps one leading dot + `[A-Za-z0-9._-]` only (path-injection guard), empty suffix allowed
    — **Why:** N is unknowable at dispatch (the node decides); prefix-scoped redemption is the only count source that stays inside the existing lazy-session economics (DA-3338).
    — **Done when:** unit tests: array session + element redemption mints indexed key; non-array session + element → 400; array session without element → 400; suffix sanitization strips separators/traversal; suffix "" allowed.
    — **Consumers affected:** SDK redeemers (P3/P4 adopt).
- [ ] **1.2** `generate_upload_targets`: array field descriptors (`{"name", "array": True}`) mint ONE prefix session (key without suffix); single fields unchanged
    — **Why:** One descriptor per field keeps the dispatch envelope at ~300 bytes (the DA-3233 8000-char cap); N descriptors would reintroduce the 413 class.
    — **Done when:** unit tests: array field → single descriptor with array flag + suffix-less key; mixed fields; single-file byte-identical to today.
    — **Consumers affected:** activities envelope.
- [ ] **1.3** `_derive_file_fields(include_extension=True)` includes array file output fields (`items.format in (binary,file)`) as `{"name", "array": True}` — schema-level extension stays empty for arrays (per-element derivation replaces `x-accept[0]`, ticket point 4)
    — **Why:** The deliberate string-only note in the code names this exact seam ("adding one needs an upload-side walker first") — this is the walker.
    — **Done when:** unit tests: array-of-file property derived with array flag; scalar file fields unchanged; non-file arrays excluded.
    — **Consumers affected:** every dispatched node's file_output_fields.

### Phase 2 (engine): stamps, sync + async parity

- [ ] **2.1** activities sync stamp: for array fields, outputs carry a LIST of local paths — stamp each `outputs[field][i] = s3://{bucket}/{key_base}/{i}{splitext(path)}`; `s3_pointers` for array fields become `{"__array_base__": ...}`-style base entries... (concretely: pointer map values become either a URI string (single) or a sentinel `{"array_base": "s3://bucket/key_base"}` the wake fold expands)
    — **Why:** The engine cannot know N before the node runs; deriving the same `{i}{ext}` from the node's reported local paths keeps redemption and stamping symmetric by construction.
    — **Done when:** unit tests: 3-element array stamps 3 index-aligned URIs with per-element extensions; single-field stamping unchanged; mixed node.
    — **Consumers affected:** node_results consumers; downstream edges.
- [ ] **2.2** workflows wake fold (DA-3313 parity): pointer values that are array-bases stamp each element of the callback outputs list via the same derivation; single pointers unchanged
    — **Why:** AC-2 — async nodes (url-loader is async-dispatched today) must produce identical arrays to the sync path.
    — **Done when:** unit tests: async callback with N-element list + array-base pointer → stamped URIs; single-pointer callback unchanged.
    — **Consumers affected:** async node runs.

## Technical Notes

- Array-session redemption is a lockstep protocol change: old SDKs receiving an array descriptor would single-file upload at the base key — nodes adopt via version pins (url-loader 1.3.0 pins its SDK bump; #3971), so no runtime coexistence risk beyond pins.
- Per-element extension: `os.path.splitext(path)` / TS equivalent — the node named its files; schema `x-accept` on items stays documentation-only for arrays.
- Suffix sanitization is a trust-boundary guard (nodes are semi-trusted): `[A-Za-z0-9._-]`, one leading dot, ≤16 chars, no separators — reject the initiate otherwise (400, named).
- The async pointer sentinel shape (`{"array_base": ...}`) is internal to the engine (activity → workflow); no API surface sees it.
- Sync stamping happens in activities (post-execute, pre-result) exactly as today for singles; no workflow-history shape changes beyond outputs content.

## Risks & Mitigations

- **Redemption API change** — additive optional field; non-array sessions reject stray elements (fail-loud, not ignore) so mix-ups surface at the boundary.
- **Key derivation drift (SDK vs engine stamps)** — one derivation rule, pinned by round-trip tests on both SDKs + engine unit tests asserting identical URIs.
- **Async pointer shape change** — sentinel only in-engine; wake fold handles both shapes; unit-pinned.
