## Implementation Phases

### Phase 1: Ceiling field + effective-bound helper (definition.py)
- [ ] **1.1** Add `hard_max_runtime_seconds: int = Field(default=7200, ge=1, description=...)` to `WorkflowNodeManifest` directly after `timeout_seconds` (`definition.py:230`), documenting it as the host-enforced ceiling that bounds `timeout_seconds`; per-node override allowed, override lands in the defining repo's PR where it is visible.
    — **Why:** the field must exist before any helper, probe, or host can reference it; placing it next to `timeout_seconds` keeps the budget pair readable.
    — **Done when:** `WorkflowNodeManifest()` without the field carries 7200; `ge=1` rejects 0/negatives.
    — **Consumers affected:** all manifest constructors (defaulted — no breakage).
- [ ] **1.2** Add `effective_runtime_seconds` property on `WorkflowNodeManifest` returning `min(self.timeout_seconds, self.hard_max_runtime_seconds)`.
    — **Why:** one place hosts derive the enforced bound; prevents each host re-implementing the min() and drifting.
    — **Done when:** property returns the declared budget when it is under the ceiling, and the ceiling when the budget exceeds it (both orderings tested in 5.1).
    — **Consumers affected:** `app.py` (3.1), CISA `job_runner.py` (#3500).

### Phase 2: Registration probe validation (__main__.py)
- [ ] **2.1** In `_probe_definition` (after the existing 86400 engine-mirror check at `:183`), add: `definition.timeout_seconds > definition.hard_max_runtime_seconds` → `report["valid"] = False` with error `timeout_seconds {N} exceeds the node's hard_max_runtime_seconds {M}`.
    — **Why:** a node declaring a budget above its own ceiling would register a budget no host may enforce — the contradiction must fail at registration, not at run time.
    — **Done when:** probe report is invalid with that error for budget 7201 / ceiling 7200; valid for 7200; default ceiling applies when the field is absent (tested in 5.2).
    — **Consumers affected:** nodes-repo CI registration convergence (nodes declaring >7200 without an explicit override now fail registration — intended gate).

### Phase 3: Inline host enforcement (app.py)
- [ ] **3.1** Change `timeout = node.definition.timeout_seconds` (`app.py:397`) to `timeout = node.definition.effective_runtime_seconds` so `asyncio.wait_for` (`:414`) honors the ceiling.
    — **Why:** inline-Lambda nodes currently bypass the ceiling entirely; the bound must be identical in both hosts or a hung inline node still runs to its raw budget.
    — **Done when:** `app.py` references `effective_runtime_seconds`; existing `test_app.py` suite passes unchanged (default ceiling ≥ typical budgets keeps behavior identical).
    — **Consumers affected:** inline-Lambda node hosts.

- `NodeTimeoutError` already emits `error_code="TIMEOUT"` — reused verbatim by the watchdog.

## Risks & Mitigation
- *Manifest field-count/round-trip parity tests fail* (test_contracts.py enumerates fields) → update the enumeration in the same phase; the field is additive with a default so wire compatibility holds.
- *Nodes-declared budgets >7200 without override now fail registration* → intended gate; the override path (5.2) is the documented escape hatch; floor-flatness (7200) fits exactly.
- *mypy strictness on the new property* → trivially typed (`-> int`); gate catches.
