- [x] **1.1** Add `hard_max_runtime_seconds: int = Field(default=7200, ge=1, description=...)` to `WorkflowNodeManifest` directly after `timeout_seconds` (`definition.py:230`), documenting it as the host-enforced ceiling that bounds `timeout_seconds`; per-node override allowed, override lands in the defining repo's PR where it is visible.
    — **Why:** the field must exist before any helper, probe, or host can reference it; placing it next to `timeout_seconds` keeps the budget pair readable.

    — **Why:** one place hosts derive the enforced bound; prevents each host re-implementing the min() and drifting.
    — **Done when:** property returns the declared budget when it is under the ceiling, and the ceiling when the budget exceeds it (both orderings tested in 5.1).
    — **Consumers affected:** `app.py` (3.1), CISA `job_runner.py` (#3500).

    — **Done when:** export of a manifest with override 9000 re-loads with 9000 intact (round-trip test in 5.1).
    — **Consumers affected:** `export_definition` consumers (node repos committing generated manifests).
    — **Done:** export_definition re-adds hard_max_runtime_seconds with #3499 comment; files: definition.py; fixes: round-trip test reworked to registry-shape reload (export file is name=slug/label=display, never directly reloadable — pre-existing)

- Field is host-side only: `build_registry_payload` maps explicitly, so the new field cannot leak into the engine request (verified `registry.py:310-315`).
- Wheels: the release workflow auto-cuts a version on merge to `main` and uploads the wheel; ticket #3500 repins CISA to that release. No release action needed inside this ticket.
- `NodeTimeoutError` already emits `error_code="TIMEOUT"` — reused verbatim by the watchdog.
- **Requirements-gap resolutions (architecture review RG1–RG3, settled with direct evidence):**
  - RG1: AC4 is a contract freeze only; raise-site canonical wiring lands with #3498 (step 4.1 states this). Answered from the ticket's own acceptance wording (the watchdog is the populator).

  - RG3 engine tolerance: `fastapi_app/core/node_registry.py:950` validates `/manifest` via `WorkflowNodeManifest.model_validate` — the always-present new key is a plain field on the same model; tolerated.
- **Recorded divergence (review WARN):** `base.py:279` `_download_deadline` still fractions the raw budget — only reachable for legacy manifests with budget > 7200 running on the new wheel before re-registration; the one-liner fix belongs to #3498 (file territory).
