# PLAN: Defuse sdk-released dispatch (drop hardcoded environment, loud sender)

**Branch**: feat/4097
**Issue**: https://github.com/betekk/canvastekk-tracker/issues/4097
**Base**: dev

## Acceptance Criteria

- [x] Every `sdk-released` dispatch carries `ref` equal to its lane environment (or the environment field is dropped and the ref carries the lane) — **field dropped**; payload = exactly `sdk_version`/`breaking`/`breaking_changes`/`released_at` (JSON-validated)
- [x] A CWN deploy following an SDK release goes green on the matching lane — guard-skip verified by logic inspection (absent `environment` → CWN #4091 guard's `!= ''` is false → skips); CWN dev env contract green (seeded, deploy green today); live proof lands on the next SDK prod release
- [x] Sender-side `continue-on-error` either removed or the step made loud on failure — **removed** from the notify step (dispatch = API POST, fails only on token/API errors; does not await CWN's deploy, so nothing extra is coupled); token step's flag untouched

## Dependency & Consumer Map

| Node (file/module) | Depends on (must precede) | Consumers (who depends on this) | Change risk |
|---------------------|---------------------------|---------------------------------|-------------|
| `.github/workflows/release.yml` notify step (publish job, prod-gated) | CWN `deploy-lambda.yml` #4091 guard (`payload.environment != ref → fail`); `repository_dispatch` always lands at default branch | SDK release lane (publish); CWN dev rebuild relay (DA-1546 chain: sdk-released → CWN deploy → nodes-deployed → CWE reseed) | low |

CWN reads exactly one payload field: `client_payload.environment` (the guard).
No other field is consumed downstream — dropping `environment` breaks nothing;
the remaining fields (`sdk_version`, `breaking`, `breaking_changes`,
`released_at`) ride along unchanged.

History note: #214 already tried flipping the value (`prod` → `uat`) — dead
end, because no constant can match a landing ref of `dev`. Absent field is the
only value-proof fix.

## Implementation Phases

### Phase 1: payload defuse + loud sender

- [x] **1.1** Delete the `"environment": "uat",` line from the notify step's `client-payload` in `.github/workflows/release.yml`
    — **Why:** the hardcoded value can never match the landing ref (`repository_dispatch` runs at the default branch, `dev`), so every SDK release fails CWN's #4091 guard red; an absent field makes the guard skip and the dispatch do useful work (rebuild CWN dev, the ladder head).
    — **Done when:** payload JSON contains no `environment` key and parses as JSON (extract + `json.loads`).
    — **Consumers affected:** CWN listener guard (skips cleanly); DA-1546 relay restored.
    — **Done:** line deleted; payload parses with exactly the 4 expected keys; files: `.github/workflows/release.yml`; fixes: none
- [x] **1.2** Remove `continue-on-error: true` from the notify step (keep it on the token-generation step)
    — **Why:** tracker #4097 AC3 — silent notify failure is invisible on the SDK lane; the dispatch is an API POST that fails only on token/API errors (it does not await CWN's deploy), so failing loud couples nothing.
    — **Done when:** the notify step has no `continue-on-error` key; the token step's flag is untouched.
    — **Consumers affected:** SDK release lane visibility only.
    — **Done:** notify flag removed; token step flag asserted untouched; files: `.github/workflows/release.yml`; fixes: none
- [x] **1.3** Verify workflow YAML validity and payload shape (YAML load; extract `client-payload` block, assert it parses as JSON and has `sdk_version`/`breaking`/`breaking_changes`/`released_at` and no `environment`)
    — **Why:** a malformed payload template silently dead-pins the relay (same class as the CWN trigger-list check).
    — **Done when:** YAML parses; payload JSON-parses with exactly the four expected keys.
    — **Consumers affected:** none beyond 1.1/1.2.
    — **Done:** YAML safe_loads; payload `${{ }}`-substituted JSON parses with exactly the 4 keys; `${{ }}` placeholders replaced pre-parse; files: `.github/workflows/release.yml`; fixes: none

## Technical Notes

- CWN guard semantics (#601): `github.event.client_payload.environment != '' && != github.ref_name` — a nonexistent property evaluates to empty string, so the absent field skips the guard.
- The publish job is `if: github.ref_name == 'prod'` — only prod releases notify; the dev-copy field value is inert until promoted, and promotions have never rewired it (hand-edited constant, #214 evidence).
- Post-fix behavior: SDK prod release → CWN dev deploy (guard skips, env contract green) → `nodes-deployed` → CWE reseed — the documented DA-1546 chain restored.
- The SDK's local `origin/HEAD` is stale (`main`, renamed away); GitHub default branch is `dev` — explicit base used.

## Dependencies

None blocking. The CWN-side hardening (#601, tracker#4091) is already merged — this ticket completes the pair.

## Risks & Mitigation

| Risk | Mitigation |
|------|------------|
| Removing `continue-on-error` reddens SDK releases on transient API blips | The dispatch only fails on token/API errors (rare); a red release naming the broken relay is exactly AC3's intent |
| CWN dev rebuild on every SDK release could be seen as waste | It is the documented DA-1546 contract; rebuild keeps the relay honest (registration + reseed fire for real) |
| Payload consumers unknown | Verified by grep: CWN consumes only `client_payload.environment` (the guard) |
