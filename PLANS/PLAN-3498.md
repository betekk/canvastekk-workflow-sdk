## Technical Notes
- Ping path needs no edit: `context.report_progress` (`context.py:248-269`) already POSTs `{execution_id, percent, message}` from `self._execution_id` — the id fixed at the source propagates.
- Engine inline mode adopts the response's `execution_id` — with no `execution_id` in inline requests, behavior is byte-identical (fallback branch).
- #3501 (CISA) injects the dispatcher's `EXECUTION_ID` env into the request it builds — the field validated here is exactly what it needs.
- Wheels: release auto-cut on merge; CISA #3501 repins the wheel carrying this change.

## Dependencies
- None blocking (#3499 merged — this branch already contains the ceiling code it references). #3501 is blocked-by this ticket.

## Risks & Mitigation
- *Engine dispatcher starts sending execution_id with a charset outside `_SLUG_RE`* → `ecs-{uuid4()}` fits today; if the engine ever widens the id format, the pattern is widened in lockstep (documented in the field description).
- *Double-park mismatch in inline mode* → cannot occur: inline requests never carry the field (engine doesn't send it), so the fallback branch is taken and the response echo is unchanged.
- *Download-deadline shrink for legacy manifests* (budget > ceiling now clamps the deadline) → intended; the 30 s floor in `_download_deadline` keeps tiny budgets viable.
